# VM verification evidence

Date: 2026-10-27. Scope: targeted behavior used by this skill, not a complete upstream conformance suite.

## Package build

The pure-Python 2.5.1 override documented in `references/nixos.md` was built successfully from upstream tag `2.5.1` (commit `9ac7caaedb55e853347c701197eccb7a245d4c07`) on `x86_64-linux` with the source hash:

```text
sha256-wRIFQQYSCsEmK7epFponyVEh9BrkjJWW8t34tDz7Ofg=
```

The successful build used `overridePythonAttrs` and `python3Packages.uv-build`. Version-only `overrideAttrs` attempts were rejected during development: the 2.4.x patch paths no longer exist and changing `build-system` without recomputing Python build inputs leaves the old backend unavailable. The final package's Nix `version` is 2.5.1; its CLI prints `ifstatecli 2.5.0`, matching the upstream tag's embedded-version wart.

Upstream evidence: [pyproject](https://codeberg.org/routerkit/ifstate/src/tag/2.5.1/pyproject.toml), [package definition](https://codeberg.org/routerkit/ifstate/src/tag/2.5.1/package.nix), [embedded version](https://codeberg.org/routerkit/ifstate/src/tag/2.5.1/src/libifstate/__init__.py#L77).

## Executed NixOS integration test

A temporary test under `/tmp` (not added to git) used `pkgs.testers.runNixOSTest` and KVM with two NixOS VMs, `foo` and `bar`. The final sandboxed build exited 0 and printed:

```text
IFSTATE_2_5_1_LIVE_FRR_WIREGUARD_OK
```

The invocation was:

```bash
nix build --impure --expr '
  let
    flake = builtins.getFlake "nixpkgs";
    pkgs = import flake { system = "x86_64-linux"; };
  in
    import /tmp/ifstate-vm-test.nix { inherit pkgs; }
' -L -o /tmp/ifstate-vm-result
```

The runner's `--impure` flag reads the temporary local test and override; the guests themselves used only their Nix closures and the isolated test VLAN. No host machine configuration was changed and no deployment command was run.

Fixture:

- `eth1`: static IPv4 underlay, `192.0.2.1/24` and `192.0.2.2/24`.
- `loop0`: dummy router IDs, `10.0.0.1/32` and `10.0.0.2/32`.
- `wg0`: WireGuard, `10.200.0.1/24` and `10.200.0.2/24`, with throwaway test keys and `!include` generated by the NixOS module.
- FRR eBGP between the underlay addresses, advertising the dummy `/32` prefixes. TCP/179 and WireGuard UDP/51820 were explicitly allowed on the test interface.
- No IfState `routing.routes` entries for the remote dummy prefixes: FRR had to provide them.

Final passing assertions:

1. Both nodes reached `multi-user.target`; `ifstate.service` reported `Result=success` while inactive.
2. The CLI printed the expected upstream 2.5.1-tag runtime string, 2.5.0.
3. `wg show wg0` succeeded and each node pinged the other's WireGuard address.
4. Each node pinged the other's dummy `/32` through FRR; the route to `10.0.0.2/32` was present via `192.0.2.2`.
5. `systemctl restart ifstate.service` reapplied configuration without a reboot; the FRR route and WireGuard connectivity remained.
6. A candidate YAML changed `loop0` from `10.0.0.1/32` to `10.0.0.11/32`; `ifstatecli --config /tmp/live.yaml apply` replaced the address live, with the old address absent and the FRR route still present.
7. An undeclared `orphan0` dummy interface was deleted by the next apply, proving the cleanup behavior.
8. WireGuard connectivity still worked after the live address change and orphan cleanup.

The log showed the expected second-apply steady state for the changed address (`addresses = 10.0.0.11/32`) and `orphan0 del`. This directly supports the skill's oneshot, live-update, FRR route-protocol ownership, `!include`, WireGuard, and orphan-cleanup guidance.

## Deliberate limits

- EVPN-VXLAN and SVD limitations are source-verified, not exercised by this two-node test.
- The optional Rust accelerator was not built or tested; the documented override uses the pure-pyroute2 fallback.
- Initrd behavior and activation semantics are verified against nixpkgs source and upstream tests, not by rebooting a host in this session.
- FRR staticd protocol 196 and foreign-static protocol 4 behavior is established from IfState and FRR source. The VM proved preservation of FRR BGP routes; it did not claim to test every routing protocol.
